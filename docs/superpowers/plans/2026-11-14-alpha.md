# Public Alpha Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** anyone on macOS 14+ Apple Silicon can download a signed,
notarized Wren `.dmg`, get updates automatically, read the docs, see the
public parity dashboard, and use passkeys.

**Architecture:** the release-please pipeline (already on `main`) cuts
versions; a release workflow builds the bundle, signs with a Developer
ID, notarizes, staples, packs a `.dmg`, and publishes an update feed.
Auto-update uses Sparkle 2 (MIT) through a thin Objective-C bridge in
`wren` because it is the maintained macOS standard with EdDSA-signed
appcasts. The parity dashboard is a static page on the docs site fed by
the CI harness JSON. Passkeys use `AuthenticationServices` platform
authenticator APIs, which need the Associated Domains / browser
entitlement and so the Apple account.

**Tech Stack:** GitHub Actions on `macos-latest`, `codesign`,
`notarytool`, `stapler`, `create-dmg` (MIT) or `hdiutil`, Sparkle 2,
`objc2-authentication-services`.

**Spec:** `docs/superpowers/specs/2026-11-13-wren-browser-design.md`
(sections 5b, 5c, 7.5 passkeys, 9, 10 Public alpha, 11, 12).
Roadmap: `docs/superpowers/plans/2026-11-13-roadmap.md`.

## Global Constraints

- All M0 to M7 constraints hold.
- **Blocked on the owner:** an Apple Developer account (personal or
  organization, an open decision). Tasks 2, 3 and 5 need it; Tasks 1, 4
  and 6 do not and land first. No task fakes signing or ships ad-hoc
  builds as releases.
- Secrets (Developer ID certificate `.p12`, its password, App Store
  Connect API key for `notarytool`, Sparkle EdDSA private key) live
  only in GitHub Actions secrets of `oscarbc96/wren`; never in the repo,
  logs or artifacts. Release jobs run only on tags from release-please.
- Release builds keep telemetry off; crash reports opt-in (spec 9).
- Bundle id `io.github.oscarbc96.wren`; update feed
  `https://oscarbc96.github.io/wren/appcast.xml`.
- Public repo identity: all commits, tags and releases under the
  owner's personal account, no other organisation names.

## Review Focus

1. **A release workflow run on a fork or a non-tag push** must never
   reach the signing step (secrets absent and job condition false).
   Pinned by `release_job_only_on_release_tags` (Task 2, workflow lint).
2. **An appcast entry whose EdDSA signature does not match** must be
   refused by the updater, leaving the installed version running.
   Pinned by `bad_signature_update_refused` (Task 3).
3. **The `.dmg` on a clean macOS user account** must open without a
   Gatekeeper warning (notarized and stapled); checked with
   `spctl -a -vv -t install`. Pinned by the `verify-release` job
   (Task 2).
4. **Parity dashboard data from a failed CI run** must not replace the
   last good data; the page shows the last good date. Pinned by
   `dashboard_keeps_last_good_run` (Task 4).
5. **A passkey request from an origin the user has not visited** must
   still show the system sheet with that origin, never auto-select.
   Pinned by `passkey_sheet_shows_origin` (Task 5).
