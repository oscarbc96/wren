spec spans several independent subsystems, so it is delivered as one plan
per milestone. Each plan produces working, tested software on its own and
is written in full only when the previous one is merged, against the code

## Cross-plan interfaces fixed now

- Crate names (unprefixed snake_case, template convention): `wren` (binary),
  `engine`, `tabs`, `store`, `omnibox`, `settings`, `themes`,
  `components`, `parity`; later `adblock_rules`, `creds`, `cdp`,
  `extensions`, `ai`, `agent`, `mcp`, `webmcp`, `reader`, `genui`,
  `routines`, `plugin_host`, `wren_plugin_api`.
- **All Servo calls live in `engine`.** No other crate imports `servo`.
  Others use the `Engine` / `WebView` traits and `EngineEvent` from M0
  Task 4; tests use `FakeEngine`.
- Tabs are addressed by `TabId(u64)`, unique per run, never reused.
- Persistent data goes through `store` (`Store` trait, SQLite impl);
  settings through the GPUI global `SettingsStore` (from the template).
- GPUI actions are named `<namespace>::<Name>` (`tab::New`,
  `tab::Close`, `omnibox::Focus`, `nav::Back`, ...), registered in the
  crate that owns the behaviour.
- Internal pages use the `wren://` scheme; only they get the `window.wren`
  bridge (M1+).

## Gate per plan

Each plan ends with: all tasks merged as self-merged squash PRs,
`mise run lint` and `mise run test` green locally, CI green, the milestone
exit from spec section 10 shown working, and the RAM benchmark run with
results committed under `docs/research/perf/`. No RAM regression beyond
10% against the previous milestone without a spec change.
