# M7 Plugins Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** native Wren plugins written in any language that compiles to
WebAssembly components run sandboxed in wasmtime with explicit
capabilities: read the page, add a sidebar panel, register agent tools,
register search providers, and register generated-page components.

**Architecture:** `wren_plugin_api` holds the WIT world (the contract)
and a Rust guest SDK. `plugin_host` (no Servo) loads components with
wasmtime's component model, checks the manifest's capabilities against
what the user granted, and exposes host functions backed by traits the
`wren` binary implements (page read through M4 `BrowserPort`, sidebar
panels through a small declarative UI tree rendered by GPUI, tools into
the M4 agent registry, search providers into M5 `search`, components
into M5's library). Each plugin gets fuel and memory limits and runs on
a worker thread; calls from the UI are async with timeouts.

**Tech Stack:** `wasmtime` (component model, Apache-2.0 WITH
LLVM-exception), `wit-bindgen` (guest SDK), `cargo-component` or
`wasm32-wasip2` target for the example plugins.

**Spec:** `docs/superpowers/specs/2026-11-13-wren-browser-design.md`
(sections 5b licence table, 7.7, 8.2 tools, 8.4 components, 10 M7).
Roadmap: `docs/superpowers/plans/2026-11-13-roadmap.md`.

## Global Constraints

- All M0 to M6 constraints hold.
- Capabilities (exact names in the WIT world): `page-read`,
  `sidebar-panel`, `agent-tool`, `search-provider`, `genui-component`,
  `network` (outbound HTTP to hosts listed in the manifest only),
  `storage` (per-plugin key/value, 5 MB). Nothing else: no filesystem,
  no clock beyond monotonic, no process spawning.
- Install shows the capability list and grants only on confirm;
  capabilities can be revoked later; a revoked call returns
  `error: capability-denied`.
- Limits per call: 10 M fuel units by default, 64 MB linear memory,
  5 s wall time; exceeding any traps that call only, the plugin stays
  loaded; three traps in a minute disable the plugin with a notice.
- Agent tools from plugins pass through the M4 policy like built-in
  tools; plugin tool output is wrapped as data.
- Plugins load from `<profile>/plugins/<id>/` (`plugin.toml` +
  `plugin.wasm`); install from a local `.wrenplugin` zip only in M7 (no
  store).

## Review Focus

1. **A plugin calling `http-fetch` to a host not in its manifest** must
   get `capability-denied`, with no request made. Pinned by
   `network_outside_manifest_denied` (Task 2).
2. **An infinite loop in a plugin tool** must trap at the fuel limit and
   return an error to the agent while the UI stays responsive. Pinned by
   `fuel_exhaustion_traps_call_only` (Task 2).
3. **A plugin's sidebar panel tree with 10,000 nodes or deeply nested
   rows** must render capped (2,000 nodes, depth 32) with a notice, not
   freeze GPUI. Pinned by `panel_tree_capped` (Task 3).
4. **Revoking `page-read` while a call is running** must make the next
   call fail with `capability-denied`. Pinned by
   `revoke_applies_to_next_call` (Task 2).
5. **A plugin search provider that returns malformed URLs** must have
   them dropped, not crash generation. Pinned by
   `plugin_search_bad_urls_dropped` (Task 4).

### Task 1: `wren_plugin_api`: WIT world and guest SDK

**Files:**
- Create: `crates/wren_plugin_api/{Cargo.toml,wit/wren.wit,src/lib.rs}`, `examples/plugins/word-count/` (Rust guest)
- Test: `crates/wren_plugin_api/tests/wit_parses.rs`, mise task `plugins:examples` (builds examples to `wasm32-wasip2`)

**Interfaces:**
- WIT package `wren:plugin@0.1.0`, world `plugin`:
  - imports: `page` (`read-snapshot(tab: u64) -> result<snapshot, error>` with `snapshot { url, title, text, outline-json }`), `http` (`fetch(req) -> result<resp, error>`), `storage` (`get/set/delete`), `log` (`info/warn`), `ui` (`update-panel(panel-id, tree-json)`).
  - exports: `describe() -> manifest-info`, `call-tool(name, args-json) -> result<string, error>`, `search(query, n) -> result<list<search-result>, error>`, `panel-event(panel-id, event-json)`, `render-component(name, props-json) -> result<tree-json, error>`.
  - `error` variant: `capability-denied`, `invalid-args(string)`, `failed(string)`.
- `plugin.toml`: `id`, `name`, `version`, `capabilities = [...]`, `network_hosts = [...]`, `tools = [{name, description, input_schema}]`, `panels = [{id, title}]`, `components = [{name, props_schema}]`.
- Guest SDK: `wren_plugin_api::export!(MyPlugin)` macro over `wit-bindgen`.
