No other apps started during measurement and no two measurements ran at once.

## Comparison and M0

M0 (`docs/research/perf/2026-11-13-m0.md`, 2026-11-13, tabs10): Chrome RSS median 462,733,312 bytes (10 samples, process tree RSS sum only). Wren M0 was pending.

M0 summed only the process tree RSS; M1 and the memory diet work report `phys_footprint` summed over every process of the profile (browser plus content processes), plus RSS for reference. This makes totals not directly comparable to M0 RSS-only figures.

Memory diet (`docs/research/2026-11-14-memory-diet.md`, 2026-11-14, tabs10, `phys_footprint` over all profile processes): Wren relief median 1,193 MB (1,251,033,088 bytes) in the part 2 alternating-run table. Current Wren tabs10 footprint median is 1,179,678,376 bytes (~1,125 MiB), within run-to-run noise of live sites and not a regression versus that measurement.

## Gap to target

Spec 11 target: at most 50% of Chrome footprint.

- tabs10: Wren 1,179,678,376 vs Chrome 793,121,240 bytes (Wren is ~149% of Chrome, ~2.99x the 50% target).
- tabs20: Wren 2,214,772,728 vs Chrome 1,387,498,608 bytes (Wren is ~160% of Chrome, ~3.19x the 50% target).

Wren remains above the 50%-of-Chrome target on this live-site workload; further diet work (tab sleep effectiveness at scale, fewer content processes, allocator and Servo-side reductions) is needed.

## Regression check

No regression above 10% against M0 on a comparable basis. M0 reported only Chrome process-tree RSS (462,733,312 bytes, tabs10) and Wren was pending, so there is no direct M0 Wren footprint baseline. Against the memory diet tabs10 `phys_footprint` measurement (relief median 1,193 MB), current Wren tabs10 is ~1.1% lower (within noise). Wren tabs20 and Chrome figures are new M1 measurements.

## Must-work exit checklist (owner, logged-in profile required)

These require the owner's logged-in profile and were not attempted here.

- **Calendar:** open Google Calendar in Wren and verify the signed-in calendar view is usable. `target/release/wren --profile-dir <owner-profile> https://calendar.google.com/`
- **Slack:** open Slack web in Wren and verify the signed-in workspace is usable. `target/release/wren --profile-dir <owner-profile> https://app.slack.com/`
- **DevTools:** start Wren with remote debugging and connect from Firefox `about:debugging` (Network location `127.0.0.1:6000`). `target/release/wren --devtools 6000 https://example.com` (or `--devtools` for default port per settings)
- **Meet:** use Meet in Wren, or route to Chrome by per-site rule if it is not usable. `target/release/wren --profile-dir <owner-profile> https://meet.google.com/`; to route: add `meet.google.com` to `sites.open_in_chrome` in settings or use "Always open this site in Chrome" from the toolbar menu, then open a Meet link and confirm it opens in Chrome.
